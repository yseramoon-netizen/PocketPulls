WHY THIS HOTFIX EXISTS
An older database object already used the player_wish_requests name but did not
contain the card_id result column expected by V67.14. V67.15 leaves that legacy
table untouched and moves wish idempotency to the collision-proof versioned
table player_wish_results_v6715.

The failed wish transaction is atomic: PostgreSQL rolls back the wallet, card,
inventory and fulfilment changes together when the column error occurs.

Founder-only preview controls remain private. Ordinary authenticated wishes do
not use a pre-release registration list. Paid orders remain locked until every
commerce prerequisite in RELEASE_CHECKLIST.md is complete.
